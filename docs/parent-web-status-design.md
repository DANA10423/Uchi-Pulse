# 親機 Web状態一覧画面 設計書

## 1. 目的

本書は、Uchi-Pulse 親機が提供するWeb状態一覧画面の基本設計を定義する。

本画面は技術的なネットワーク監視画面ではなく、家庭内で「誰・何が、現在どういう状態なのか」を簡潔に確認することを目的とする。

---

## 2. 対象範囲

本書では以下を対象とする。

- 全体通知の表示
- 家族用端末の一覧表示
- 設備用端末の一覧表示
- 通信状態の表示
- 家族用端末の入室可否表示
- 親機メモリ状態とSQLite情報の組み合わせ方針

以下は本書の対象外とする。

- 簡易スケジュール表示
- 子機設定用Web画面
- Webからの子機設定変更
- 詳細な通信診断画面
- 最終確認時刻や最新イベントの常時表示

簡易スケジュール機能は GitHub Issue #7 で別途扱う。

---

## 3. 画面構成

Web状態一覧画面は、主に以下の3領域で構成する。

1. 全体通知
2. 家族用端末一覧
3. 設備用端末一覧

概念例:

```text
┌────────────────────────────────────┐
│             Uchi-Pulse             │
├────────────────────────────────────┤
│ 全体通知                           │
│ ・ご飯できました                   │
│ ・ポストに投函がありました         │
├────────────────────────────────────┤
│ 家族                               │
│ 名前        通信状態      入室可否 │
│ お父さん    オンライン    OK       │
│ お母さん    オンライン    会議中   │
│ 子ども      オフライン    NG       │
├────────────────────────────────────┤
│ 設備                               │
│ 名前        通信状態               │
│ ポスト      オンライン             │
│ 玄関        未確認                 │
└────────────────────────────────────┘
```

画面の具体的なCSS、色、レイアウト幅、レスポンシブ対応などの詳細は実装時に決定する。

---

## 4. デバイス分類

`devices.device_type` をWeb一覧での利用分類に使用する。

初期仕様では以下の2種類とする。

| `device_type` | 用途 | Web表示分類 |
|---|---|---|
| `PERSON` | 家族が使用する端末 | 家族 |
| `FACILITY` | ポスト、玄関等の設備に設置する端末 | 設備 |

`device_type` はハードウェア種類や通信方式を示すものではない。

家族用端末と設備用端末は、通信プロトコル上は同じ汎用子機として扱う。

---

## 5. 家族用端末一覧

### 5.1 表示対象

以下を満たすデバイスを対象とする。

- `devices.enabled = 1`
- `devices.device_type = PERSON`

### 5.2 表示項目

家族一覧では以下を表示する。

| 項目 | 内容 |
|---|---|
| 名前 | `devices.name` |
| 通信状態 | `DeviceState.status` |
| 入室可否 | `DeviceState.room_access_status` |

最終確認時刻、最新イベント、IPアドレス等は一覧に常時表示しない。

### 5.3 通信状態

通信状態は以下の3種類を表示する。

| 内部状態 | Web表示 |
|---|---|
| `INITIAL_WAIT` | 未確認 |
| `ONLINE` | オンライン |
| `OFFLINE` | オフライン |

通信状態は親機稼働中のメモリ上で管理する。

### 5.4 入室可否

入室可否は以下の4種類とする。

| 内部状態 | Web表示 | 意味 |
|---|---|---|
| `UNSET` | 未設定 | 入室可否が設定されていない |
| `OK` | OK | 入室可能 |
| `NG` | NG | 入室を控えてほしい |
| `MEETING` | 会議中 | 会議・通話等のため入室を控えてほしい |

入室可否は家族用端末のみ表示する。

通信状態と入室可否は独立した状態として扱う。

そのため、例えば以下の表示を許容する。

```text
お父さん    オフライン    会議中
```

端末が `OFFLINE` になったことを理由に、入室可否を自動的に変更・非表示にはしない。

---

## 6. 設備用端末一覧

### 6.1 表示対象

以下を満たすデバイスを対象とする。

- `devices.enabled = 1`
- `devices.device_type = FACILITY`

### 6.2 表示項目

設備一覧では以下を表示する。

| 項目 | 内容 |
|---|---|
| 名前 | `devices.name` |
| 通信状態 | `DeviceState.status` |

設備用端末には入室可否を表示しない。

最終確認時刻、最新イベント、IPアドレス等は一覧に常時表示しない。

---

## 7. 全体通知

### 7.1 基本方針

全体通知は、家庭内で現在知らせる必要がある情報を表示する。

例:

- ご飯できました
- ポストに投函がありました

通知は単純なイベント履歴一覧とは区別する。

### 7.2 状態変化

通知の表示状態は、イベントまたはマクロ処理によって変化させる。

```text
通知発生イベント
      │
      ▼
通知状態 ON
      │
      ▼
Webに表示

通知消去イベント
      │
      ▼
通知状態 OFF
      │
      ▼
Webから非表示
```

通知の消去は、別のイベントを受信して状態を変化させる方式を基本とする。

自動消去時間は本設計の必須仕様としない。

### 7.3 管理方針

現在表示中の通知状態は親機メモリ上で管理する。

通知の元となったイベントは `events` テーブルへ履歴として保存される。

通知状態そのものを専用DB項目として保持する設計は、現段階では採用しない。

---

## 8. データ取得と責務分離

Web画面は、SQLiteと親機メモリ上の現在状態を組み合わせて表示する。

| 表示情報 | 取得元 |
|---|---|
| 名前 | `devices.name` |
| 利用分類 | `devices.device_type` |
| 有効／無効 | `devices.enabled` |
| 通信状態 | `DeviceState.status` |
| 入室可否 | `DeviceState.room_access_status` |
| 全体通知 | 親機メモリ上の通知状態 |

基本責務は以下とする。

```text
SQLite
  ├─ devices
  │    └─ 登録済みデバイス情報
  │
  └─ events
       └─ 過去に発生したイベント履歴

メモリ
  ├─ DeviceState
  │    ├─ 通信状態
  │    └─ 入室可否
  │
  └─ 通知状態
       └─ 現在Webへ表示する全体通知
```

DBは「登録情報と過去の事実」を保持し、メモリは「現在の状態」を保持する。

## 9. 親機起動時の表示

親機起動時は、`devices` から有効なデバイスを取得して `DeviceState` を生成する。

通信状態は以下とする。

```text
status = INITIAL_WAIT
last_seen_at = 未設定
```

そのため、親機再起動直後でも登録済みデバイスはWeb一覧に表示され、通信状態は「未確認」と表示される。

### 9.1 入室可否の復元

入室可否の現在値はDBに専用項目として保存しない。

親機起動時に、各家族用デバイスについて `events` の履歴から最新の入室可否イベントを取得し、`DeviceState.room_access_status` を復元する。

```text
DeviceState生成
      │
      ├─ status = INITIAL_WAIT
      ├─ last_seen_at = 未設定
      └─ room_access_status = UNSET
                      │
                      ▼
             最新の入室可否イベント検索
                      │
             ┌────────┴────────┐
             │                 │
           あり              なし
             │                 │
             ▼                 ▼
      最新状態へ復元          UNSET
```

通信状態はイベント履歴から復元しない。

---

## 10. 一覧に常時表示しない情報

メインの状態一覧は情報量を抑え、家庭内の現在状態を素早く確認できることを優先する。

以下は常時表示しない。

- 最終正常受信時刻
- 最新イベント
- 最新イベント発生時刻
- IPアドレス
- HEARTBEAT回数
- 再送回数等の通信診断情報

将来必要となる場合は、詳細画面や管理画面として別途設計する。

---

## 11. 画面更新

Web画面は、親機メモリ上の現在状態が変更された場合に、その状態を反映できる構造とする。

対象となる主な状態変化は以下とする。

- `INITIAL_WAIT` → `ONLINE`
- `ONLINE` → `OFFLINE`
- `OFFLINE` → `ONLINE`
- 入室可否の変更
- 全体通知の発生
- 全体通知の消去

具体的な更新方式（定期ポーリング、Server-Sent Events、WebSocket等）は本概要設計では固定しない。

初期実装では、構成を過度に複雑化しない方式を選択する。

---

## 12. 非対象機能

以下は本Web状態一覧画面とは分離する。

### 12.1 簡易スケジュール

簡易スケジュールは別機能として扱う。

GitHub Issue #7 を参照する。

### 12.2 子機設定

子機設定をWeb画面から行う方式は採用しない。

子機のGPIO割り当て、イベント設定等は別途定義された設定方式で行う。

### 12.3 通信診断

IPアドレス、最終受信時刻、HEARTBEAT等の技術情報を本画面の主表示とはしない。

---

## 13. Web一覧表示の確定仕様

現段階で以下を確定事項とする。

- `device_type` は初期仕様として `PERSON` / `FACILITY` とする。
- Web一覧は「全体通知」「家族」「設備」に分ける。
- 家族一覧は「名前」「通信状態」「入室可否」を表示する。
- 設備一覧は「名前」「通信状態」を表示する。
- 入室可否は家族用端末のみ表示する。
- 通信状態と入室可否は独立して表示する。
- OFFLINE時でも入室可否は保持・表示する。
- 最終確認時刻や最新イベントは常時表示しない。
- 全体通知はイベントで表示状態を変化させる。
- 通知消去も別イベントによる状態変化として扱う。
- 通知の自動消去時間は必須仕様としない。
- スケジュール機能は本画面設計から分離する。
