# Uchi Pulse システム概要設計書

## 1. 文書概要

### 1.1 目的

本書は、家庭内での「ゆるいコミュニケーション」を実現する **Uchi Pulse**
システムの概要設計を定義する。

Uchi Pulse
は、家族ごと・場所ごとに配置した小型端末（Node）から、ボタン操作やセンサー入力などのイベントを家庭内ネットワーク上の親機（Hub）へ通知し、家の中で発生した小さな「合図」や「気配」を共有することを目的とする。

### 1.2 システム名称

-   システム名称: **Uchi Pulse**
-   プロジェクト識別名: `uchi-pulse`

「Uchi」は「うち・家庭内」、「Pulse」は「鼓動・小さな信号」を意味し、家庭内で発生する小さなイベントを伝えるシステムというコンセプトを表す。

------------------------------------------------------------------------

## 2. システムコンセプト

Uchi Pulse
は、スマートフォンのメッセージングアプリのような文章中心のコミュニケーションではなく、ボタン、センサー、表示装置などを利用した簡単な操作によって、家庭内の状態や意思をゆるく共有する。

代表的な利用例を以下に示す。

-   家族が専用ボタンを押してイベントを通知する。
-   「入室可」「入室不可」などの意思をボタン操作で通知・表示する。
-   ポストへの投函をセンサーで検出して通知する。
-   各部屋や場所に設置したセンサーのイベントを通知する。
-   Node側のGPIO出力を使用してLED等の表示装置を制御する。
-   将来的に新しい入力・出力機器を追加する。

特定用途専用端末を多数設計するのではなく、共通のNodeハードウェアと設定によって複数の用途に対応できる構成を基本方針とする。

------------------------------------------------------------------------

## 3. システム構成

Uchi Pulse は、主に以下の3種類のソフトウェアプロジェクトで構成する。

  --------------------------------------------------------------------------------------------------
  プロジェクト            役割                                               主な実行環境
  ----------------------- -------------------------------------------------- -----------------------
  `uchi-pulse-hub`        親機。Node管理、イベント受信、状態管理             Raspberry Pi Zero W /
                                                                             Zero 2 W

  `uchi-pulse-node`       子機。ボタン、センサー、GPIO入出力、イベント送信   Raspberry Pi Pico W /
                                                                             Pico 2 W

  `uchi-pulse-config`     Node初期設定ツール                                 PC

  `uchi-pulse-core`       将来必要になった場合の共通データ型・処理           共通ライブラリ
  --------------------------------------------------------------------------------------------------

概念構成は以下のとおり。

``` text
                         家庭内ネットワーク
                              Wi-Fi
                                │
                    ┌─────────────────────┐
                    │   Uchi Pulse Hub    │
                    │ Raspberry Pi Zero   │
                    │   W / Zero 2 W      │
                    └──────────┬──────────┘
                               │
                 ┌─────────────┼─────────────┐
                 │             │             │
              Wi-Fi          Wi-Fi         Wi-Fi
                 │             │             │
        ┌────────▼──────┐ ┌───▼──────────┐ ┌▼─────────────┐
        │ Pulse Node #1 │ │ Pulse Node #2│ │ Pulse Node #N│
        │ Pico W/2 W    │ │ Pico W/2 W   │ │ Pico W/2 W   │

        └───────────────┘ └──────────────┘ └──────────────┘
```

## 4. Uchi Pulse Hub

### 4.1 役割

`uchi-pulse-hub` はUchi Pulseシステムの親機として動作する。

主な責務は以下とする。

-   Nodeからの通信受信
-   Nodeの自動登録
-   Node一覧の管理
-   Nodeのオンライン／オフライン状態管理
-   イベント受信
-   EVENTに対するACK応答
-   Nodeから受信した情報の処理
-   将来的な通知・表示機能への連携

### 4.2 Node登録

Hubは電源投入後、Nodeから有効な通信を受信した際にNodeを認識する。

HELLOはNode登録の代表的なメッセージであるが、Nodeから正常なEVENT等を受信した場合も、そのNodeが通信可能であることを示すものとして扱う。

Hub上のNode一覧は、通常動作中に積極的に削除しない。

Hub自身の電源OFFによって管理情報を失う構成を許容し、再起動後はNodeからの通信によって再度Nodeを認識する。

### 4.3 オンライン状態

Nodeから正常な通信を受信した場合、そのNodeをオンラインとして扱う。

一度オフラインと判定されたNodeについても、その後正常なデータを受信した場合はオンライン状態へ復帰させる。

------------------------------------------------------------------------

## 5. Uchi Pulse Node

### 5.1 役割

`uchi-pulse-node` は家庭内の各場所または家族向けに設置する子機である。

主な責務は以下とする。

-   イベントボタン入力
-   センサー入力
-   GPIO入力
-   GPIO出力
-   Hubへのイベント通知
-   Hubへの生存通知
-   設定情報の保持

### 5.2 ハードウェア

Nodeの基本ハードウェアとして以下を想定する。

-   Raspberry Pi Pico W
-   Raspberry Pi Pico 2 W

Wi-Fi機能を使用してHubと通信する。

### 5.3 イベントボタン

イベントボタンはNodeの基本構成として必須とする。

ボタンの具体的な機能はNodeごとの設定によって決定する。

例:

-   呼び出し
-   帰宅通知
-   入室可否
-   簡易的な意思表示
-   その他の家庭内イベント

### 5.4 GPIO

Nodeの入出力機能はGPIO端子への割り当てとして定義する。

これにより、特定用途専用のハードウェア設計に固定せず、将来的な拡張に対応する。

想定例:

-   ボタン
-   開閉センサー
-   投函検知センサー
-   LED
-   入室可否表示
-   ブザー
-   その他のデジタル入出力機器

------------------------------------------------------------------------

## 6. Uchi Pulse Config

### 6.1 役割

`uchi-pulse-config` はNodeの初期設定を行うためのツールである。

NodeをPCへUSB接続し、必要な設定を書き込む。

### 6.2 設計方針

Node自身にWeb設定画面は実装しない。

設定専用ツールを使用することで、Nodeファームウェアを簡潔に保つ。

設定対象として、少なくとも以下を想定する。

-   Node識別情報
-   Wi-Fi設定
-   Hub接続設定
-   ボタン機能
-   GPIO割り当て
-   通信パラメータ

------------------------------------------------------------------------

## 7. 通信概要

### 7.1 通信方式

HubとNodeは家庭内Wi-Fiネットワークを利用して通信する。

アプリケーションレベルのデータ形式には **JSON** を使用する。

### 7.2 メッセージ種別

基本メッセージとして以下を使用する。

  種別          方向         用途
  ------------- ------------ ----------------------------------
  `HELLO`       Node → Hub   Nodeの存在通知・初期認識
  `HEARTBEAT`   Node → Hub   Nodeの生存通知
  `EVENT`       Node → Hub   ボタン・センサー等のイベント通知
  `ACK`         Hub → Node   EVENT受信確認

詳細なJSON構造については通信仕様書で定義する。

------------------------------------------------------------------------

## 8. EVENTとACK

Nodeから送信するEVENTはACK対象とする。

HubはEVENTを正常に受信した場合、簡潔なACKをNodeへ返す。

基本パラメータは以下とする。

  項目            初期値 備考
  ------------- -------- ----------
  ACK待ち時間       60秒 設定可能
  再送回数           3回 設定可能

ACKはできるだけ単純な構造とし、イベント受信確認という責務に限定する。

------------------------------------------------------------------------

## 9. HEARTBEATとオンライン判定

Nodeは定期的にHEARTBEATをHubへ送信する。

基本パラメータは以下とする。

  項目                初期値 備考
  ----------------- -------- ----------
  HEARTBEAT間隔          3分 設定可能
  OFFLINE判定時間        3分 設定可能

HEARTBEATが所定時間内に到着しなかった場合、Hubは対象Nodeをオフラインとして扱う。

ただし、オフライン状態のNodeから、その後HELLO、EVENT、HEARTBEAT等の正常な通信を受信した場合は、オンラインへ復帰させる。

したがって、オンライン／オフラインは固定的な登録状態ではなく、Nodeとの現在の通信状態を表す。

------------------------------------------------------------------------

## 10. Nodeのライフサイクル

基本的なNodeの動作イメージを以下に示す。

``` text
電源ON
  │
  ▼
初期化
  │
  ▼
Wi-Fi接続
  │
  ▼
HubへHELLO
  │
  ▼
通常動作
  │
  ├── ボタン入力 ──────┐
  │                    │
  ├── センサー入力 ────┼──> EVENT送信 ──> ACK待ち
  │                    │                    │
  └── GPIO入力 ────────┘                    ├─ ACK受信 → 完了
  │                                         │
  │                                         └─ Timeout → 再送
  │
  └── 一定時間経過 → HEARTBEAT送信
```

``` text

  │
  ▼
初期化
  │
  ▼
通信待受開始
  │
  ├── HELLO受信
  │      └─ Node認識 / ONLINE
  │
  ├── HEARTBEAT受信
  │      └─ Node ONLINE更新

  ├── EVENT受信
  │      ├─ Node ONLINE更新
  │      ├─ イベント処理
  │      └─ ACK送信
  │
  └── Node監視
         └─ 所定時間通信なし → OFFLINE
```

## 12. 設計上の基本方針

### 12.1 シンプルさを優先する

家庭内ネットワーク上で使用する小規模システムであるため、必要以上に複雑な通信制御やNode管理を導入しない。

### 12.2 Nodeを汎用化する

用途ごとに異なるファームウェアを作るのではなく、可能な限り共通の
`uchi-pulse-node` と設定情報によって動作を変更する。

### 12.3 Hubを中心とした構成

Node同士が直接通信するのではなく、基本的にHubを介してイベントや状態を扱う。

### 12.4 一時的な通信断を許容する

Wi-Fiの一時切断などを考慮し、NodeはEVENTのACK確認と再送を行う。

HubはNodeをオフラインと判定しても登録そのものを削除せず、正常な通信が再開した時点でオンラインへ復帰させる。

### 12.5 将来の拡張を妨げない

初期実装では必要最低限の機能としつつ、GPIO出力、表示装置、新しいセンサー、イベント種別などを追加できる構造とする。

## 16. まとめ

Uchi
Pulseは、家庭内で発生する小さなイベントを「Pulse」として扱い、家族間で簡単に共有するためのシステムである。

システムは、

-   **Hub** --- 家庭内イベントを集約する親機
-   **Node** --- ボタンやセンサーによってPulseを発生させる子機
-   **Config** --- Nodeを設定するためのツール

を中心に構成する。

初期段階ではシンプルな構成を維持しながら、GPIOと設定機能を利用して様々な家庭内用途へ拡張できることを基本設計方針とする。
